商家端 Flutter 工程目前只有本地演示登录、总览和商品 CRUD；订单、排队及真实商家 API 尚未实现。因此插件独立仓库先运行，不改 Flutter 商家端、学生端、PHP 和生产环境。Windows 和 macOS 都是插件正式目标，不能沿用商家端“Windows 正式、macOS 预览”的旧定位。

## 形态和生命周期

采用**独立桌面程序 + 同进程本机服务**：商家明确安装并手动启动；本机页面负责摄像头设置、预览和统计。第一阶段从终端启动，未来安装包提供快捷方式及菜单栏／托盘控制。默认不随系统自动启动。升级时先停采集、保存非敏感配置、验证签名后替换程序；卸载时关闭进程并让用户选择清除本机设置。视频和长期身份轨迹默认不存储。

商家端后续仅检查本机签名发现文件与一次性握手，兼容版本才显示“插件可用”，异常时显示原因及最后更新时间。商家端不直接获得原始画面；汇总结果的跨进程合同和身份绑定待原型稳定后与商家端对话协调。

## 当前云端建议

“低配电脑”应通过实测确定瓶颈。摄像头采集、解码或抽帧仍发生在本机或经过授权的边缘网关；把识别放云端并不能免去这些步骤。连续过线事件不能仅靠间隔较长的视觉语言模型截图可靠恢复。因此优先比较：

1. 本机或校园内网边缘设备轻量专用检测 + 本地短时跟踪与计数；
2. 云端专用检测服务 + 本地或服务端短时跟踪与计数；
3. 千问／豆包视觉模型用于配置校准、抽样复核和离线标注辅助。

阿里云百炼目前列有 `qwen3.8-flash` 视频输入，火山方舟列有视频理解接口。它们的“支持视频”并不等于已验证连续人数计数。只用模拟视频做横向评测；没有真实场景授权时不调用真实监控。官方来源：[千问视觉能力](https://help.aliyun.com/zh/model-studio/vision-model)、[千问价格](https://help.aliyun.com/zh/model-studio/model-pricing)、[火山方舟视频理解](https://docs.volcengine.com/docs/ark/video-understanding?lang=zh)。

## ETA、无摄像头模式与试点门槛

当前页面只显示排队人数。未来 ETA 需绑定可审计的订单／叫号／人工服务完成事件，给出样本量、更新时刻及区间；没有足够事件则保持空值。可另做商家人工填报人数或无摄像头模式，作为门店不愿接入视频时的选择。

试点前需确认画面来源、学校和摄像头管理方权限、使用目的、提示标识、数据保留、第三方云接收方及网络地域。尤其不能将原为公共安全安装的画面直接改作商业统计用途。默认不做人脸识别、不跨店追踪、不保存可识别长期轨迹；防盗只保留研究方向，不自动认定或指认个人。参考：[个人信息保护法第二十六条](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)、[人脸识别技术应用安全管理办法](https://www.cac.gov.cn/2025-03/21/c_1744174262156096.htm)。
